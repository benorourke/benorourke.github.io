Python Dataclasses: A Practical Guide

Posted on 1 May 2026

Why dataclasses

Before @dataclass (added in Python 3.7), a simple data-holding class meant writing __init__, __repr__, and __eq__ by hand. Dataclasses generate all of that for you.

from dataclasses import dataclass

@dataclass
class Pipeline:
    name: str
    schedule: str
    enabled: bool = True

That’s it. You get a constructor, a readable repr, and equality comparison for free.

Defaults and default factories

from dataclasses import dataclass, field

@dataclass
class Pipeline:
    name: str
    tags: list[str] = field(default_factory=list)  # mutable default — must use field()

The default_factory pattern catches people out: you can’t write tags: list = [] because the same list object would be shared across all instances.

When to use Pydantic instead

Dataclasses don’t validate types at runtime — if you pass enabled="yes" it won’t complain. Reach for Pydantic when:

  • You’re parsing external input (API responses, config files)
  • You need coercion or validators
  • You want .model_dump() / .model_json_schema()

For internal data passing where the types are under your control, dataclasses are lighter and have zero dependencies.
