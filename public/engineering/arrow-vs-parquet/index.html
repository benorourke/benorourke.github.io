Arrow vs Parquet: When to Use Which

Posted on 15 Jun 2026

The short answer

Parquet is a storage format — it’s designed to sit on disk (or S3) efficiently.
Arrow is an in-memory format — it’s designed to move data between systems without copying.

You’ll often use both: read a Parquet file into an Arrow table, process it in memory, write it back as Parquet.

Parquet

Parquet is a columnar file format. Because it stores data column-by-column rather than row-by-row, it compresses extremely well and lets query engines skip entire columns they don’t need.

import pyarrow.parquet as pq

table = pq.read_table("data/sales.parquet", columns=["date", "revenue"])

Good for:

  • Long-term storage
  • Files on S3, GCS, HDFS
  • Query engines like DuckDB, Spark, Athena

Arrow

Arrow defines a language-agnostic in-memory columnar layout. The point is zero-copy reads — a Python process and a Rust process can share the same Arrow buffer without serialising.

import pyarrow as pa

table = pa.table({"x": [1, 2, 3], "y": [4.0, 5.0, 6.0]})

Good for:

  • Passing data between processes (IPC)
  • Flight (Arrow’s gRPC-based data transfer protocol)
  • Avoiding pandas’ memory overhead

When you need both

import pyarrow.parquet as pq

# Read from disk into Arrow in-memory table
table = pq.read_table("sales.parquet")

# Process in Arrow (zero-copy column access)
revenue = table.column("revenue")

# Write back
pq.write_table(table, "sales_processed.parquet")
